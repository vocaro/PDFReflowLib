## Devanagari

[Open Logic Project Hindi cumulative reader](https://zenodo.org/records/21921856), [direct PDF](https://zenodo.org/records/21921856/files/00_OpenLogic_hi-Deva-IN_CUMULATIVE_READER.pdf), 17 pages, 212,719 bytes, SHA-256 `bc7d4f6280d2e3da427715b7ca2df5335e8057ad0c0dcbcadef8c18e27360468`. The publisher record declares [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) and identifies this as a machine-assisted adaptation without human translation review. Physical page 5 was read against its rendered source and the reflowed output. The inherited PDFKit layer corrupts pre-base vowel order (`दिखाइए` becomes `िदखाइए`), so `--language hi-IN --ocr always --reference-images always` uses Vision at the library's default 180 DPI and includes the complete original page image. The contract explicitly requires that original-page image rather than allowing an unrelated formula crop to satisfy image presence.

The page-5 contract pins six snippets that actually match the source, including `दिखाइए`, the four number-set labels and `ये सभी अनंत समुच्चय हैं`; all 8 checks pass. The full run recognizes and reflows 17/17 pages, includes 50 images, and has no `ocrFailed` or `pageImageFallback` on the reviewed page. EPUBCheck has zero errors and warnings, and progress reaches 100%. Converter peak RSS was 218,218,496 bytes against a 512 MiB ceiling; peak host pressure level was normal (1). The EPUB has 5,485,187 bytes, SHA-256 `9cd0df9e7fe9ac556d9f91a51c974686b43278e6c4367ccc1c17ca809502d857`. A second serial host run passed the same 8 checks, recognized 17/17 pages and emitted 50 images, at peak RSS 212,353,024 bytes; its EPUB bytes differ, so the contract checks reviewed content rather than binary equality.

OCR is **not** fully accurate. On page 5, source `परिभाषा` is sometimes `रिभाषा`, `समुच्चय` is sometimes `समुख्वय`, and mathematical notation is noisy. The retained original page image supplies a readable visual reference for these errors; none of the erroneous text is asserted correct. Translation accuracy, the other 16 pages' OCR fidelity, and the [Zenodo handwriting workbook](../hindi-candidates-44/record.md)'s broken native ToUnicode are not qualified by this admission.

## Host boundary

A restricted command sandbox ran this same release binary and source at explicit 180 DPI but Vision failed on all 17 pages with `ocrFailed`; the output became page images. The exact same binary under host execution succeeded 17/17 pages, and the targeted host corpus gate passed twice for Hindi. The earlier 240-DPI trial also failed with a `CVPixelBuffer` error. Corpus qualification therefore applies to the recorded macOS host execution context and 180-DPI setting; a sandboxed OCR run is a visible failure, not evidence of text fidelity.
